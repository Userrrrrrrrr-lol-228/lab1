# Lab API — лабораторные анализы

REST-сервис учёта лабораторных анализов (Spring Boot + PostgreSQL).
Заказчик сдаёт **образец**, к образцу назначаются **анализы** по выбранной **методике**,
в рамках анализа записываются **измерения**. По подтверждённым измерениям считается результат.

## Сущности и связи
- `users` 1—N `samples` (заказчик → его образцы)
- `samples` 1—N `analyses` (образец → анализы)
- `analysis_methods` 1—N `analyses` (методика → анализы по ней)
- `analyses` 1—N `measurements` (анализ → измерения)

Удаление родителя каскадно удаляет дочерние записи (`ON DELETE CASCADE`).
Ограничения в БД: `NOT NULL`, внешние ключи, `CHECK` на статусы и на `min_value < max_value`,
`UNIQUE` на имя методики и на пару (образец, методика).

Статусы: образец `NEW → IN_ANALYSIS → DONE | REJECTED`,
анализ `NEW → IN_PROGRESS → DONE | FAILED`, или `CANCELLED`.

## Запуск
```bash
cp .env.example .env        # поменяй пароли
docker compose up -d        # Postgres + таблицы + тестовые данные + пользователь app_user
./mvnw spring-boot:run      # приложение на :8080
```
Приложение подключается к БД под `app_user`, у которого есть только SELECT/INSERT/UPDATE/DELETE.
Чтобы пересоздать БД с нуля: `docker compose down -v` (обязательно после обновления до задания 4 — изменилась таблица `users`).

## CRUD
`/api/users`, `/api/analysis-methods`, `/api/samples`, `/api/analyses`, `/api/measurements`
(GET, GET /{id}, POST, PATCH /{id}, DELETE /{id}).

## Бизнес-операции
| Операция | Что делает | Когда запрещена (409) |
|---|---|---|
| `POST /api/analyses/{id}/start` | анализ → `IN_PROGRESS`, образец → `IN_ANALYSIS` | анализ не `NEW`; образец закрыт; материал образца не подходит методике |
| `POST /api/analyses/{id}/measurements` `{"value": 7.0}` | добавляет измерение | анализ не `IN_PROGRESS`; значение вне `min..max` методики |
| `POST /api/measurements/{id}/confirm` | подтверждает измерение | анализ не `IN_PROGRESS`; уже подтверждено |
| `POST /api/analyses/{id}/complete` | считает среднее по подтверждённым; разброс > `maxSpread` → `FAILED`, иначе `DONE`; если все анализы образца `DONE` — образец `DONE` | анализ не `IN_PROGRESS`; подтверждённых измерений меньше 2 |
| `POST /api/samples/{id}/reject` | образец → `REJECTED`, его незавершённые анализы → `CANCELLED` | образец уже `DONE` или `REJECTED` |

Каждая операция выполняется в одной транзакции, данные остаются согласованными.

## Безопасность (Spring Security)
HTTP Basic, без сессий: логин и пароль передаются в каждом запросе. Пароли хранятся в БД в виде BCrypt-хеша.

**CSRF.** Для всех изменяющих запросов (POST/PATCH/DELETE) нужен токен:
`GET /api/auth/csrf` → сервер ставит cookie `XSRF-TOKEN` и возвращает `token`,
его передают в заголовке `X-XSRF-TOKEN` (вместе с cookie).

**Регистрация** `POST /api/auth/register` `{"name", "username", "password"}`:
пароль не короче 8 символов, обязательны буквы и цифры (иначе 400); логин уникален (иначе 409).
Пользователь всегда получает роль `CUSTOMER`, переданное поле `role` игнорируется.
`GET /api/auth/me` возвращает текущего пользователя. Пароль в ответах не возвращается никогда.

**Состояние учётной записи:** `enabled = false` означает, что пользователь заблокирован и войти не может (401).
Блокирует лаборант: `PATCH /api/users/{id}` `{"enabled": false}`.

**Роли**
| Роль | Что может |
|---|---|
| `CUSTOMER` (заказчик) | смотреть методики; сдать образец **от своего имени**; смотреть и отклонять **только свои** образцы |
| `LAB` (лаборант) | всё: CRUD всех сущностей, все бизнес-операции, управление пользователями |

Доступ к URL задаётся в `SecurityFilterChain`, а проверки, зависящие от контекста (чей это образец), — в `@PreAuthorize`.
Бизнес-ограничения действуют для всех ролей: например, заказчик не может отклонить свой образец, если тот уже `DONE`/`REJECTED` (409).

**Ответы при ошибках** (`{"error": "..."}`, без внутренних подробностей):
`401` — не аутентифицирован, неверный пароль или учётная запись заблокирована;
`403` — недостаточно прав или нет/неверный CSRF-токен; `400`/`409` — нарушение правил валидации/бизнес-логики; `404` — не найдено.

Тестовые пользователи: `lab / Lab12345` (LAB), `ivan / Ivan12345`, `anna / Anna12345` (CUSTOMER), `blocked / Blocked123` (заблокирован).

## Postman
Импортируй `postman/lab-api.postman_collection.json` и запусти коллекцию целиком (Runner):
0. Аутентификация — CSRF-токен, регистрация (успех, дубль логина, слабый пароль, попытка взять роль LAB), 401/403,
1. CRUD — создаёт данные по каждой сущности (от имени `lab`),
2. Бизнес-операции — сценарий от запуска анализа до завершения и отклонения, включая запрещённые случаи,
3. Права заказчика — что зарегистрированный заказчик может и чего не может, блокировка учётной записи,
4. Удаление.

По умолчанию запросы идут от имени `lab` (авторизация на уровне коллекции), папка 3 — от нового заказчика.
CSRF-заголовок подставляет pre-request скрипт коллекции, cookie Postman хранит сам.
